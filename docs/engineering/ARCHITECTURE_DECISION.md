# 技术路线决议（ADR-001）

- 状态：**已定稿，待实施**
- 日期：2026-11-07
- 版本：工程冻结基线 v2.1.0 之上
- 适用范围：640×1280 红外/近红外睑板腺影像的腺体分割与临床量化
- 约束：旧 UNet 家族降级为**基线对照组**；新架构为默认；core 契约、可安装、可迁移能力保持不变

---

## 1. 问题画像（选型的唯一依据）

| 维度 | 事实 | 对架构的硬影响 |
|---|---|---|
| 图像 | 单通道红外/近红外，原始 1280×640，统一到 640×1280（Batch 后实际为 640 高 × 1280 宽） | 高分辨率是刚需；16× 下采样后结构只剩 40×80，细腺体直接消失 |
| 目标 | 睑板腺：细长、分支、走向近垂直、宽度 3–8 px（640×1280 下） | 需要 ≤8× 的下采样 + 骨架/边界约束；HD95 对断裂极敏感 |
| 数据量 | 999 例去重配对（影像/腺体/眼睑），患者级 694/153/152 划分（239/50/49 患者） | 从零训练大模型必然过拟合；优先预训练权重 |
| 跨设备 | 多台红外相机采集，亮度/对比度/噪声分布差异明显 | 归一化 + 强度域增强 + 域泛化策略比改主干更有效 |
| 部署 | 用户日常端为 8 GB 笔记本 GPU；论文机器可能 16/24 GB | 训练必须支持分块；推理必须可 tiled |
| 工程 | 两端交付（Windows WebUI + Linux CLI）、离线可装、Windows 为主 | 避免需要本地编译 CUDA 算子的方案 |

## 2. 主干候选对比与结论

| 候选 | 细长结构 | 小数据（999 例） | 显存（640×1280，AMP） | 推理成本 | 工程风险 | 结论 |
|---|---|---|---|---|---|---|
| **SegFormer (MiT-B2)** | 中上：最高分辨率阶段 stride=4，保留 1/4 细节；1/4 输出直接解码 | 好：ADE20K/ImageNet 预训练权重可用 | 训练 ~4–6 GB（384×768 分块、batch 1–2）；整图 ~10–12 GB 不适用 8 GB | 中：B2 约 27 M 参数，tiled 推理约为 UNet 的 2–3× | 低：纯 PyTorch 实现，无自定义 CUDA 算子 | **默认主干** |
| Swin-UNet（纯 Transformer U 形） | 差：patch 4 + 4 级下采样，最细 1/4 但窗口化注意力对细线连续性不友好 | 差：全注意力参数多、无强预训练时收敛慢 | 高：窗口注意力显存随分辨率上升明显 | 高 | 中 | 不采用（只作文献对照） |
| VM-UNet / U-Mamba（状态空间） | 中：SSM 长程建模好，但 2D 扫描顺序会割裂细长连通性，需靠 clDice 补 | 中：参数不大但需从头训练 | 中 | 中 | **高**：`mamba-ssm`/`causal-conv1d` 需编译 CUDA 内核，Windows/离线安装不可控，跨机器复现风险大 | 备选，仅当目标机为 Linux + 固定 CUDA 时启用 |
| nnU-Net（2D 自配置配方） | 中上：patch 取自中位形状、深监督、强增强 | **最好**：小数据医学分割事实标准 | 可控：自配置 batch/patch | 中 | 低（但引入外部依赖与独立环境） | **不作为默认模型，作为训练配方来源 + 外部基线** |
| 现有 UNet / AttentionUNet / WRCANet | 中：stride 16 为主 | 中 | 低 | 低 | 低（已稳定） | **保留为基线对照组** |
| MGD-PriorNet v1（FCAS/ASAB/APG-DD） | 中上：各向异性条带卷积适配细长结构 | 中 | 低 | 低 | 低（已实现） | **保留为消融分支**（贡献点：结构先验，可迁移到新主干） |

**决议：默认主干 = SegFormer-B2 编码器 + 高分辨率融合解码器（下称 MGD-Former）。**

具体形态（必须落到可实现粒度）：
- 编码器：MiT-B2，4 个阶段 stride = 4/8/16/32，通道 64/128/320/512，预训练权重来自 ADE20K（`nvidia/segformer-b2-ade-512x512`，仅取 encoder）。
- 解码器：**不用 SegFormer 原生 MLP 头**，改为
  - stage1（1/4, 64ch）与 stage2（1/8, 128ch）做 1×1 降维 → 与 stage3/4 上采样特征做逐级融合；
  - 输出 stride = 4，最后 4× 双线性上采样 + 3×3 conv 回到 640×1280；
  - **深监督**：在 1/4、1/8、1/16 三个尺度各接 1×1 辅助头，权重 1.0 / 0.5 / 0.25；
  - 双任务头：腺体 1 通道 + 眼睑 1 通道（沿用现有双通道契约）。
- 参数量估算 ~26–30 M；FP32 权重 ~110 MB（与现有 UNet 同级，部署无额外负担）。

**为什么是它（而不是"更大更强"的模型）**：本问题的瓶颈是**细节保留**与**小数据泛化**，不是长程依赖。SegFormer 的 1/4 高分辨率阶段 + 预训练权重正好命中这两点；而 mamba 系的收益主要体现在长程建模，对本问题边际收益低、工程代价高。nnU-Net 的价值在配方（深监督、强增强、中位形状 patch），我们直接吸收配方而不引入其整套框架。

**风险与回退**：若 MGD-Former 在 5 折上不稳定（折间 Dice 标准差 > 0.05）或低于 nnU-Net 配方基线，回退顺序为：① MGD-Former + nnU-Net 增强/深监督调参；② nnU-Net 2D 作为默认、MGD-Former 作对照；③ 保留现有 UNet + clDice 作为交付兜底。回退不改变接口与 run 目录契约。

## 3. 损失与监督决议

| 组件 | 取舍 | 理由 |
|---|---|---|
| Dice + CE | 保留，权重 0.4 / 0.4 | 区域重叠 + 像素稳定梯度，双通道分别计算后加权 |
| **clDice** | **加入**，权重 0.2，前 10% 训练轮 warmup（0→0.2） | 细长分支结构的拓扑连通性；直接对应 HD95/断裂问题；warmup 避免早期骨架噪声 |
| 边界损失 | 可选，权重 0.1（Boundary loss / 距离图加权 CE） | 对 HD95 有帮助；但实现与调参成本中等，先作为开关，默认关闭 |
| 深监督 | **加入**（1/4、1/8、1/16） | 小数据下加速收敛、稳定梯度；成本仅多 3 个 1×1 头 |
| 眼睑辅助任务 | **保留**（λ=0.2–0.3） | 提供解剖先验（ROI/分母），且 R_loss 与 Meiboscore 需要眼睑通道；不是装饰性多任务 |
| Focal Tversky | 保留为可选项 | 高召回场景（筛查）备用；默认不用，避免与 clDice 叠加导致训练不稳 |
| 骨架一致性（显式） | 不单独加 | clDice 已覆盖可微骨架一致性，重复加权会放大噪声 |

**决策**：默认 `0.4·Dice + 0.4·CE + 0.2·clDice + 0.25·眼睑辅助 + 深监督`；所有项在 YAML 可调，旧损失全部保留可选。

## 4. 训练配方

- **精度**：AMP（CUDA）/ 关闭（CPU）；分块 384×768 起，OOM 自动降级到 320×640。
- **EMA**：decay 0.999，评估用 EMA 权重（对 999 例小数据收益稳定，成本约 +1 份参数显存）。
- **优化器**：AdamW，lr 1e-4（预训练编码器）/ 1e-3（随机初始化头），weight_decay 1e-4，warmup 5% + cosine 到 1e-6。
- **增强**：弹性形变、旋转 ±10°、缩放 0.85–1.2、水平翻转（**仅当腺体分布近似对称时才开**，本数据近垂直走向，水平翻转安全，垂直翻转禁用）、强度扰动（gamma 0.8–1.25、CLAHE clip 0.01–0.03、高斯噪声、模糊 0–1 px）。这是针对**跨设备**的核心手段。
- **多尺度训练**：0.75×/1.0×/1.25× 随机缩放（保持 2:1 宽高比）。
- **TTA**：水平翻转 + 0.75/1.0/1.25 三尺度（8×）；用于论文指标与最终交付，不用作训练时监控。
- **集成**：5 折权重取平均（概率平均）作为最终交付模型；论文同时报告单折与集成。

## 5. 评价协议（与工程冻结基线一致，不推翻）

- 数据：持久化 70/15/15（`dataset_splits.json`）+ **5 折交叉验证**（同一份 signature，不重切）。
- 指标：Dice、IoU、HD95、ASSD、**clDice**、Precision/Recall、Meiboscore 分类准确率、R_loss（眼睑分母）、单例耗时、显存。
- 统计：**bootstrap 1000 次** 给 95% CI；模型间 **Wilcoxon signed-rank** + Holm 校正；报告效应量（Cliff's delta 可选）。
- 口径：所有论文数字必须是**独立测试集**（与训练互斥）；训练期自评只能标"训练集自评"。
- 反泄漏硬约束：`reference_report.json` 必须带 `split_signature` 与数据集 sha 级信息；缺 signature 的报告判为无效。

---

## 6. 不确定性估计与临床可信

- **默认**：TTA 熵 + 概率熵（已实现），输出像素级不确定度图与置信度分。
- **温度标定**：在 val 上拟合单一温度 T（最小化 NLL），只改校准不改排序；成本极低，**纳入**。
- **MC Dropout**：推理时开 dropout（p=0.1）跑 8 次，成本约 8×，**默认关闭**，仅在"低置信度复核"场景按需开启。
- 临床规则：置信度 < 0.6 或模糊像素占比 > 10% 标记"建议复核"（沿用现有契约）。

## 7. 自监督预训练

- 结论：**本轮不做，预留接口**。
- 理由：999 例无标注影像对 MAE/SimCLR 而言规模偏小，收益不确定性高；而 ADE20K 预训练编码器已提供强初始化。强行做自监督会消耗 4–8 小时 GPU 且难以证明增益。
- 预留：编码器加载逻辑支持 `pretrained=imagenet|ade20k|mae:<path>|none`；若后续补充无标注数据（同设备 >3000 例），再启动 MAE-lite。

## 8. 双轨兼容（新架构 + 旧基线）

| 层 | 决议 |
|---|---|
| 模型注册表 | `MODEL_NAMES` 追加 `MGD-Former` 并设为**默认**；旧 `UNet/AttentionUNet/WRCANet/MGD-PriorNet` 全部保留、可加载、可评测 |
| 输出契约 | 统一 `(N, 2, H, W)` 双通道；单通道旧权重由 `detect_out_channels` 自动适配（已有能力） |
| 配置 | YAML 增 `model.name` 与 `model.pretrained`，默认 `MGD-Former`；baseline 用同一份配置只改 `model.name` |
| 权重/manifest | 同一 manifest 状态机；训练产物一律 `verified=false` 草稿，`mgd-verify --evaluate` 才能转正 |
| 评测 | 同一 `evaluate_pairs` 与同一持久化划分；消融跑同一 Test，输出 Wilcoxon/LaTeX |
| 交付端 | UI/CLI 默认列出新架构，旧家族保留在下拉中；Windows 与 Linux 共用同一内核与回归集 |

## 9. 工作量、显存与时间估算（估算值，非实测）

| 档位 | 训练分块 | batch | 单 epoch 估算 | 20 epoch / 折 | 5 折总计 |
|---|---|---|---|---|---|
| 8 GB（本机 4060） | 384×768 AMP | 1–2 | 8–15 min | 3–5 h | 15–25 h |
| 16 GB | 512×1024 AMP | 2 | 6–10 min | 2–3.5 h | 10–17 h |
| 24 GB | 640×1280 AMP | 2 | 5–8 min | 1.5–2.5 h | 8–12 h |

推理（tiled 384×768，单例）：MGD-Former 估算 0.8–1.2 s（现有 UNet 实测 0.37 s/例为锚，约 2–3×）；8 GB 显存可跑。

**本轮只做 1–2 epoch 冒烟**，只报吞吐与显存，不报精度。

## 10. 实施顺序（下一步执行）

1. 注册 `MGD-Former`（编码器 + 高分辨率融合解码器 + 深监督 + 双通道），默认架构切换。
2. 损失组合落地为可配置项（clDice warmup、深监督权重、眼睑辅助）。
3. 配置/run 目录/manifest/评测协议接入双轨（同一套，不新增分叉）。
4. 冒烟：1–2 epoch、AMP、384×768，记录每 epoch 时间、峰值显存、单例推理耗时；跑通 `mgd-train`/`mgd-eval`/`mgd-verify` 全链路。
5. 文档更新：`KNOWN_LIMITATIONS` 增补"新架构尚无完整训练结论"，`FREEZE_BASELINE` 更新架构矩阵。

## 11. 留给论文线的可替换依据（占位）

- 主干对比表中"细长结构/小数据"的判断需引用：SegFormer（Xie et al., 2021）、Swin-UNet（Cao et al., 2022）、VM-UNet（Ruan et al., 2024）、nnU-Net（Isensee et al., 2021）。
- clDice（Shit et al., 2021）；Boundary loss（Kervadec et al., 2019）；深监督（Lee et al., 2015）。
- 温度标定（Guo et al., 2017）；bootstrap CI 与 Wilcoxon 的检验协议为标准做法。
- 待文献矩阵到位后可替换措辞与引用编号，**不影响上述工程决议**。

## 12. ADR-002：可解释性必须过忠实度检验

- 状态：**已定稿并实施**（v2.4.0）
- 背景：`generate_heatmap(prob, gray)` 只是概率图伪彩，信息量等于分割掩膜本身，把它当
  "热力图/归因" 展示是伪解释。
- 决议：
  1. 概率伪彩在 UI 中必须标注「概率伪彩（非归因）」；真归因走 `mgd.core.explain`
     （LayerCAM / Score-CAM / 遮挡敏感度）。
  2. 任何归因图进入报告/UI 前，必须给出忠实度证据（deletion / insertion AUC 与随机对照、
     verdict pass/fail）；verdict=fail 的归因图只能标注为「仅供排查参考」。
  3. 归因实现禁止：内部偷偷降采样、返回全零/全 NaN 图糊弄（必须显式抛错）、
     hook 泄漏（异常路径必须清理）。
- 验收门：`quality/gates` 与 `tests/test_explain.py` 的「假归因防回归门」
  （attribution=随机噪声 → verdict 必须为 fail）。

## 13. ADR-003：指标必须注册且带定义/单位/来源

- 状态：**已定稿并实施**（v2.4.0）
- 背景：临床量化指标若没有定义公式、单位与文献来源，就会产生「看起来专业但无法解释」
  的数值——在医疗语境下这是不可接受的。
- 决议：
  1. 一切进入报告/UI 的量化指标必须在 `mgd.core.quantification.registry` 注册
     （`MetricSpec(key, name_zh, definition, unit, source, requires, higher_is_better)`）。
  2. `source` 只允许三类词表：文献标识（"Arita et al. 2008" / "Pult & Nichols 2016"）
     或 "engine-defined"（工程定义，必须显式承认）。
  3. 没有定义的指标不许写进代码；报告渲染时同时给出定义与来源。
  4. 缺失输入一律 NaN + 说明，绝不用 0 冒充（沿用 v2.3.0 纪律）。
- 验收门：`quality/gates/g03_metric_registry_integrity.py`（131 项检查）。

## 14. ADR-004：分级体系不可互换

- 状态：**已定稿并实施**（v2.4.0）
- 背景：Arita meiboscore（4 级，切点 1/3、2/3）与 Pult Meiboscale（5 级，切点 25/50/75）
  对同一缺失率会给出不同级别（如 30% → Arita 1 / Pult 2）。
- 决议：
  1. `mgd.core.grading` 同时提供两套分级，输出必须并排呈现并附「不可直接互换」固定文案。
  2. 禁止在报告中只展示其中一套而不声明口径；禁止把一套的级别直接映射成另一套。
  3. Arita 的「≤5% 归 0」是本项目操作化（与 `clinical.meiboscore_from_rloss` 对齐），
     在 definition 中显式注明，不是文献原义。
  4. NaN 输入返回 -1 + warning，不抛异常、不猜级别。
- 验收门：`quality/gates/g16_grading_crosscheck.py`（101 点逐点交叉验证）。
